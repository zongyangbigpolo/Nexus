# Feature Specifications

This folder contains design specifications generated by the `spec-author` agent.

## Naming Convention

```
{JIRA-ID}-{FeatureName}.spec.md
```

**Examples:**
- `ENG-1234-MultiDatacenterSupport.spec.md`
- `ENG-5678-BrowserPolicyEnhancements.spec.md`

## Workflow

```
┌─────────────────┐       ┌───────────────────┐       ┌──────────────┐
│  /feature-spec  │  ──►  │   spec-author     │  ──►  │  .spec.md    │
│  (prompt)       │       │   (agent)         │       │  (this dir)  │
└─────────────────┘       └───────────────────┘       └──────────────┘
                                                              │
                                                              ▼
                          ┌───────────────────┐       ┌──────────────┐
                          │ article-publisher │  ◄──  │   Review     │
                          │   (handoff)       │       │   (user)     │
                          └───────────────────┘       └──────────────┘
                                   │
                                   ▼
                          ┌───────────────────┐
                          │   Confluence      │
                          │   (published)     │
                          └───────────────────┘
```

## File Structure

Each `.spec.md` file follows the [Design Spec Template](https://example.atlassian.net/wiki/spaces/DOCS/pages/461832544/Design+Spec+Template):

```markdown
# {Feature Name} - Design Specification

| Field | Value |
|-------|-------|
| JIRA | {JIRA-ID} |
| Author | AI-Generated |
| Date | {YYYY-MM-DD} |
| Status | Draft |

---

## Overview
## Requirements
## High-Level Design
## Low-Level Design
## Security
## Testability
```

## Publishing to Confluence

After reviewing the spec, use the `article-publisher` handoff:

```
@article-publisher action=create source=file path=specs/ENG-1234-FeatureName.spec.md space=DOCS
```

Or use the `/article` prompt:

```
/article action=create source=file path=specs/ENG-1234-FeatureName.spec.md space=DOCS title='Feature Name Design Spec'
```

## Git Workflow

1. Spec files are **version controlled** in Git
2. Can be reviewed in PRs before Confluence publish
3. History preserved for auditing
4. Can diff changes between versions
